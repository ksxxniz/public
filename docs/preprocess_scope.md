# 전처리 지원 범위와 한계 (정규화 1.0)

1단계 전처리가 무엇을 처리하고 무엇을 처리하지 못하는지 정리한 문서입니다. 발표에서 한계를 밝힐 때 근거로 아래 탈출률 표를 함께 씁니다. 표는 `uv run python -m datagen.escape_rate --out 파일.md` 로 다시 뽑을 수 있습니다.

## 1. 입력

- 파일 형식: `.txt`, `.md`, `.html`, `.htm` (decisions.md ②)
- 문자 인코딩: UTF-8, BOM 이 있는 UTF-16·32, CP949(EUC-KR 포함), 히라가나가 섞인 Shift-JIS. 그 밖은 charset-normalizer 판별에 맡깁니다.
- 크기: 파일은 8,000,000바이트(`preprocess.load.MAX_DOCUMENT_BYTES`), 원문은 2,000,000자(`preprocess.normalize.MAX_DOCUMENT_CHARS`)까지 받습니다. 넘으면 읽거나 정규화하기 전에 `DocumentTooLongError` 를 냅니다. NFKC 로 글자가 늘어나는 문서(`ﷺ` 한 글자가 18자가 됨)도 늘어난 길이가 2,000,000자를 넘으면 거부합니다.
- Python 3.11(3.11.15 이상, 유니코드 14.0)에서 씁니다. 유니코드 버전이 다르면 정규화 결과가 달라질 수 있어 import 할 때 경고가 뜨고, HTML 파서는 3.11.15 보다 낮으면 `HtmlParserUnavailableError` 를 냅니다.

## 2. 처리하는 것

## 4. 알려진 한계

**입력**
- EUC-JP 일본어, 짧은 GB2312 중국어, 히라가나 없이 한자·가타카나만 있는 짧은 Shift-JIS 글은 CP949 로 잘못 읽힐 수 있습니다.

**HTML**
- 숨김 판정은 인라인 `style`, 옛 색 속성(`font color`, `body text`, `bgcolor`), `hidden` 속성과 태그만 봅니다. `<style>` 블록의 클래스·ID 규칙(`.x{display:none}`)으로 숨긴 글은 정리본에는 남지만 숨김으로 표시되지 않습니다. (권장 항목, 아직 안 함)
- 외부 CSS·JS 로 만든 숨김은 범위 밖입니다. 화면을 실제로 그려 보는 헤드리스 브라우저가 필요합니다.
- 속성 글은 `alt`, `title`, `aria-label`, `meta` 설명, `input type=hidden` 값만 정리본에 넣습니다. `data-*`, `class`, `href`, `src` 같은 다른 속성과 닫는 태그에 붙은 속성(`</p title="...">`) 안의 글은 넣지 않습니다. 그래서 이 속성들 안의 인코딩(`href` 의 Base64 등)도 ⑤ 에서 풀지 않습니다.
- `>` 없이 문서가 끝난 태그 조각(`<p title="...` 로 끝나는 문서) 안의 글은 브라우저와 같이 버립니다.
- `script`·`style` 안의 코드도 숨김 텍스트로 정리본에 남기므로, 스크립트가 많은 웹 문서는 청크가 늘어납니다.

**Markdown·txt**
- 4칸 들여쓰기 코드 블록은 코드로 보지 않습니다.
- 링크 정의(`[label]: url "title"`)는 `title` 만 표시하고, `label` 은 주석 형태(`[label]: #`)이면서 제목이 없을 때만 표시합니다. 제목은 다섯 줄까지만 봅니다. 표시하지 않은 글도 정리본에는 그대로 있습니다.
- MD 안 HTML 의 숨김 표시는 Python 3.11.15 미만이면 건너뜁니다. 정리본은 같습니다.

**인코딩 복원**
- 최대 3겹까지만 풉니다. 복원한 글 안에 Base64·Hex·URL 이 일부만 섞여 있으면 그 부분은 풀지 않습니다. (ROT13 은 일부만 있어도 풉니다.)
- Base64 는 16자 이상, Hex 는 16자리 이상, URL 은 `%XX` 가 3개 이상 이어져야 후보가 됩니다. 숫자로만 된 Hex 는 영어 단어로 풀릴 때만 받아들입니다(주문번호·전화번호 오탐 방지).
- 푼 결과는 UTF-8 로 읽고, NUL 이 많이 섞인 것(영어 UTF-16)과 한글이 대부분인 UTF-16 은 UTF-16 으로 읽습니다. 중국어·일본어 UTF-16 은 놓칩니다. 깨진 바이트·제어 문자가 약 10% 넘게 섞이면 버립니다. 20자 미만의 짧은 결과는 깨진 글자가 하나도 없어야 합니다. 깨진 바이트를 많이 섞어 희석한 인코딩은 놓칩니다.
- ROT13 은 영어에만 동작하고, 흔한 영어 단어 비율로 판단하므로 짧은 문장(3단어 미만), 숫자·글자에 붙여 쓴 단어(`vtaber1nyy`), 단어마다 다른 단어를 끼워 넣어 비율을 낮춘 글은 놓칩니다.
- 밑줄·하이픈으로 다른 글자에 붙은 Base64(`key_aWdu...`)는 앞 글자와 한 덩어리로 보여 놓칠 수 있습니다. `/` 로 나뉜 경로 조각은 따로 풀어 봅니다.
- 이미지 data URI 도 다른 Base64 와 같이 검사합니다. 실제 이미지는 바이너리라 버려지고, SVG 처럼 글자로 풀리는 것은 복원 결과에 남습니다.
- 본문에 글자로 적힌 HTML 엔티티와 `\u` 표기는, 글자·숫자나 보이지 않는 문자로 풀리는 숫자 표기(`&#105;`, `&#x69;`, `\u0069`, `\u{69}`, `\U00000069`)가 하나라도 있을 때만 풉니다. `&amp;`·`&lt;`·`&eacute;` 같은 이름 엔티티와 기호로 풀리는 표기(`&#60;`, `&#169;`)만 있으면 풀지 않습니다. 64자 안에 붙어 있는 표기는 한 덩어리로 보고, 그 덩어리가 있는 줄 전체(앞뒤 200자까지)를 풀어서 하나의 복원 결과로 남깁니다. 그래서 복원 결과의 위치는 표기 하나가 아니라 그 줄을 가리킵니다.
- 코드 문서에는 `\u0041`·`\uc548` 같은 표기가 정상적으로 쓰이므로 복원 결과가 생깁니다. Base64 예시와 같이 `decoded_count` 보다 복원 내용을 1차 분류기가 판정하게 해야 합니다. 윈도 경로의 `\u` 뒤에 16진 숫자 4개가 오는 경우(`C:\Users\u1234`)도 풀립니다.
- 한 문서의 복원 결과가 10,000개(`MAX_DECODED_SEGMENTS`)를 넘거나 복원한 글자가 ③·④ 를 다시 거친 뒤 모두 1,000,000자(`MAX_DECODED_CHARS`)를 넘으면 앞부분만 풀지 않고 `DocumentTooLongError` 로 거부합니다.

**유니코드·홈글리프**
- 악센트가 붙은 닮은꼴 글자(`ё`, `ά`)는 라틴 문자로 바꾸지 않습니다.
- 단어 전체를 키릴 문자로 쓴 영어 단어는 섞인 단어가 아니라서 바꾸지 않습니다. (여유 시 항목)
- 쪼갠 자모 앞에 남는 자모가 붙으면(`ㅋㅁㅜㅅㅣ`) 조립하지 않습니다. 정상 채팅(`ㅋㅋㅋ`, `좋아ㅇㅋ`)을 바꾸지 않기 위한 규칙입니다.

**크기 상한·청킹**
- 청크가 1000개를 넘는 문서는 `DocumentTooLongError` 로 거부합니다. 앞부분만 검사하고 넘기면 뒤쪽이 우회 구멍이 되기 때문입니다. 파일 크기·원문 글자 수·복원 결과 상한도 같은 이유로 거부합니다. 상한값은 통합 담당과 확정합니다.
- 처리 시간 상한은 두지 않았습니다. 시간으로 끊으면 같은 문서라도 컴퓨터 속도에 따라 결과가 달라져 학습과 서빙이 어긋납니다. 대신 위 크기 상한으로 처리 시간을 묶습니다(6절).

## 5. 범위 밖 (모델이 배우도록 데이터로 넘김)

- PDF·DOCX 고유의 숨김 기법
- 한자 대체(無視), 초성 표기(ㅇㅈ ㅈㅅ), 야민정음, 리트 스피크(1gn0r3), 무작위 띄어쓰기·구두점 삽입

## 6. 처리 시간

`uv run python -m preprocess.perf_report --out 파일.md` 로 다시 잴 수 있습니다. 아래는 3주차에 글자 토크나이저(`PREPROCESS_TOKENIZER=char`)로 잰 값입니다. 크기는 UTF-8 바이트이고, 문서는 한국어·영어 문장에 Base64 예시가 조금 섞인 정상 문서입니다. 정규화는 `normalize_document`, 전체는 청크까지 만든 `split_document` 시간입니다. 글자 토크나이저는 공백이 아닌 글자마다 토큰 하나로 세서 청크 수가 실제보다 많습니다. 그래서 1MB 문서는 청크 상한(1000개)을 넘지만, 시간을 재려고 상한을 끄고 쟀습니다.
