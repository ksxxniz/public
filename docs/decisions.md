# 팀 결정 기록

`common/config.py` 의 값과 함께 관리합니다. 한쪽을 바꾸면 다른 쪽도 같은 PR 에서 고치고, 전원 리뷰를 받습니다. 결정을 바꿀 때는 기존 내용을 지우지 않고 변경 내용을 덧붙입니다.

## ① 좌표 규칙

- `Span` 은 `[start, end)` 반열린 구간이고, 파이썬 문자열 인덱스 단위입니다.
- `DecodedSegment.span` 과 `StageResult.evidence_span` 은 `chunk.raw_text` 기준입니다. 문서 기준 위치는 `chunk.span.start` 를 더해서 구합니다.
- 정리본(`text`)에서 찾은 위치는 `Chunk.raw_span()` 으로 원문 위치로 바꿔서 내보냅니다.
- 관련 코드: `common/schema.py` 맨 위 설명
- (2026-10 추가) `raw_span()` 의 끝은 "다음 글자의 원문 시작 위치"까지 잡습니다. 예전 계산은 NFD 자모가 합쳐진 글자(macOS 에서 온 한글)에서 끝을 잘랐습니다. 대신 구간 바로 뒤에서 지워진 글자(제로폭 등)도 하이라이트에 포함됩니다.
- (2026-10 추가) `offset_map` 은 감소하지 않습니다. 감소하면 `Chunk` 생성이 에러를 냅니다.
- (2026-10 추가) 위치 단위는 파이썬 코드포인트입니다. 웹(JS)은 UTF-16 단위라 이모지·태그 문자가 2칸이 되므로 web 에서 바꿔 씁니다.
- (2026-10 추가) `raw_span()` 은 원문 시작 위치가 같은 다음 글자들(한 원문 묶음에서 함께 나온 글자, 예: `ﬁ́` → `fí`)을 건너뛰고, 위치가 바뀌는 글자의 시작 위치까지 잡습니다. 묶음의 앞 글자만 골라도 원문 묶음 전체가 잡힙니다.

## ② 지원 파일 형식

- `.txt`, `.md`, `.html`, `.htm` 만 지원합니다. PDF 는 지원하지 않습니다.
- 관련 코드: `common/config.py` → `SUPPORTED_EXTENSIONS`
- (2026-10 추가) 문자 인코딩은 UTF-8, BOM 이 있는 UTF-16·32, CP949(EUC-KR 포함), 히라가나가 섞인 Shift-JIS(CP932) 일본어를 읽고 그 밖은 charset-normalizer 판별에 맡깁니다. EUC-JP 일본어, GB2312 중국어(특히 짧은 글), 히라가나 없이 한자·가타카나만 있는 짧은 Shift-JIS 글(회사명 등)은 CP949 로 잘못 읽힐 수 있어 지원 범위 밖입니다.

## ⑥ 전처리 원칙

- 원문 좌표는 바이트가 아니라 디코딩된 문자열 기준입니다.
- 숨김 텍스트(흰 글씨, `display:none`, 주석 등)는 지우지 않고 `text` 에 남기며, 위치는 `Chunk.transform_spans` 에 표시합니다. 실제 RAG 의 AI 가 읽는 내용과 검사 대상을 같게 하기 위해서입니다.
- 인코딩 복원 결과(`decoded_segments`)는 본문에 섞지 않고, 별도 청크로 만들어 1차에 함께 통과시킵니다. 그 청크의 위치는 원문의 인코딩 구간을 가리킵니다.
- 변환 개수는 `TransformLog`, 위치는 `Chunk.transform_spans` 에 따로 담습니다. 로그 `reason` 칸에는 개수만 들어갑니다.
- Python 은 3.11 로 고정합니다. 파이썬 버전마다 유니코드 데이터가 달라 NFKC 결과가 바뀔 수 있습니다(3.11 = 14.0, 3.12 = 15.0). 3단계 학습도 3.11 에서 하고, 청크 `meta.unicode_version` 으로 확인합니다.
- (2026-10 추가) 쪼개 쓴 자모(`ㄱㅗㅇㄱㅕㄱ`)는 NFKC 가 아니라 별도 단계에서 조립합니다. 자모로 쓰인 덩어리 안에서만, 단어 단위로 "남는 자모 0개, 음절 2개 이상"일 때만 조립합니다. 정상 채팅(`ㅋㅋㅋㅠㅠ`, `좋아ㅇㅋ`)을 바꾸지 않기 위해서입니다. 조립한 음절 수는 `TransformLog.jamo_assembled` 에 남깁니다.
- (2026-10 추가) `TransformLog.decoded_count` 는 그 청크의 `decoded_segments` 개수입니다. 복원 방법(Base64, 태그 문자 등)과 상관없이 셉니다. 종류는 `decoded_segments[].method` 로 구분하고, 숨긴 태그 글자 수는 `tag_chars_decoded` 에 따로 있습니다.
- (2026-10 추가) 태그 문자 조각이 2개 이상인 청크에는 조각별 결과 뒤에, 그 청크의 조각을 순서대로 이어 붙인 결과를 하나 더 넣습니다(method `unicode_tag`, 위치는 첫 조각 시작부터 마지막 조각 끝까지). 보이는 글자 사이에 숨긴 글자를 하나씩 끼워 해독 결과를 한 글자씩 조각내는 우회를 막기 위해서입니다.
- (2026-10 추가) 공백류(탭·줄바꿈 등)를 뺀 제어 문자(Cc), 점자 공백(U+2800), Cf 가 아닌 기본 무시 문자(U+17B4~17B5, U+2065, U+FFF0~FFF8 등)도 지우고 `zero_width_removed` 로 셉니다. 몽골 자유 변형 선택자(U+180B~180D, U+180F)는 `variation_selector_removed` 로 셉니다.
- (2026-10 추가) 유니코드 버전이 14.0.0(Python 3.11)이 아니면 `preprocess.normalize` 를 import 할 때 `RuntimeWarning` 을 띄웁니다. 3단계 학습 환경이 3.11 인지 확인하는 용도입니다.
- (2026-10 추가) ② HTML 은 태그를 지우고, 블록 태그는 줄바꿈으로, 엔티티는 원래 글자로 바꿉니다. 숨김 텍스트(인라인 스타일과 `font color`·`bgcolor` 같은 옛 색 속성으로 숨긴 글, 주석, CDATA, 브라우저가 주석으로 처리하는 `<?…>`·`<!…>`, 표준이 아닌 DOCTYPE, `script`·`style`·`template`·`noscript` 안의 글, `alt`·`title`·`aria-label`·`meta` 설명·`input type=hidden` 값)는 정리본에 남기고, 위치와 이유를 `hidden_text_found`(note 에 이유)로 남깁니다. HTML 파서는 Python 3.11.15 이상에서만 돌고, 그보다 낮으면 `HtmlParserUnavailableError` 를 냅니다.
- (2026-10 추가) ② Markdown 은 원문 자체가 AI 입력에 가까워서 글자를 하나도 바꾸지 않고 표시만 합니다. 주석(`<!-- -->`, `[//]: # (...)`), 이미지 `alt`, 링크·이미지 `title`, MD 안 HTML 의 숨김 텍스트가 대상이고, 코드 블록·인라인 코드 안은 표시하지 않습니다. MD 안 HTML 의 표시는 HTML 파서가 없는 Python(3.11.15 미만)에서는 건너뜁니다. 정리본은 같으므로 학습용 `normalize_text` 는 그대로 씁니다.
- (2026-10 추가) ⑤ 인코딩 복원은 Base64(표준·URL-safe, 패딩 유무, 줄바꿈된 것), Hex(`\x69`·`0x` 형태 포함), URL(`%XX` 3개 이상 연속), ROT13(흔한 영어 단어 비율이 크게 오를 때만, 근처에 rot13 언급이 있으면 기준을 낮춤)을 풉니다. 푼 바이트는 UTF-8 로 읽고 NUL 이 많거나 한글이 대부분이면 UTF-16 으로 읽으며, 깨진 바이트·제어 문자가 약 10% 이하이면서 글자가 하나 이상 있을 때만 받아들입니다(20자 미만은 깨진 글자가 없어야 함). 숫자로만 된 Hex 는 영어 단어로 풀릴 때만 받아들입니다. 최대 3겹까지 풀고, 겹친 속에 ROT13 이 있어도 풉니다. 이미지 data URI 는 따로 건너뛰지 않고 같은 검사로 거릅니다. 본문에 글자로 적힌 HTML 엔티티(`&#105;`)와 `\u0069` 같은 표기는 글자·숫자나 보이지 않는 문자로 풀리는 숫자 표기가 있을 때만, 그 표기가 있는 줄(앞뒤 200자까지)을 통째로 풀어 `html_entity`·`unicode_escape` 로 넣습니다. `&amp;`·`&eacute;` 같은 이름 엔티티와 기호로 풀리는 표기만 있으면 풀지 않습니다. 복원 결과는 ③·④ 를 다시 거쳐 `decoded_segments` 에 넣고 본문에는 섞지 않습니다.
- (2026-10 추가) 크기 상한: 파일 8,000,000바이트(`preprocess.load.MAX_DOCUMENT_BYTES`), 원문과 NFKC 뒤 정리본 2,000,000자(`preprocess.normalize.MAX_DOCUMENT_CHARS`), 복원 결과 10,000개·1,000,000자(`preprocess.encoding.MAX_DECODED_SEGMENTS`, `MAX_DECODED_CHARS`)를 넘으면 청크 상한(④)과 같이 `DocumentTooLongError` 로 거부합니다. 파일·원문 크기는 읽거나 정규화하기 전에 봅니다. 처리 시간 상한은 두지 않습니다. 시간으로 끊으면 컴퓨터 속도에 따라 같은 문서의 결과가 달라져 학습과 서빙이 어긋나기 때문입니다.
- (2026-10 추가) 처리 시간 목표: 문서 하나(정규화+청킹)를 10KB 이하는 p95 50ms 이하, 100KB 는 p95 500ms 이하, 1MB 는 p95 5초 이하로 둡니다. 3주차 측정값(글자 토크나이저, 클라우드 2코어)은 10KB 27ms, 100KB 256ms, 1MB 2.3초(p95, 세 형식 중 가장 느린 값)입니다. 실제 토크나이저 기준은 팀 PC 에서 `uv run python -m preprocess.perf_report --out 파일.md` 로 다시 재서 확정합니다.
- (2026-10-26 측정) 실제 토크나이저(`xlm-roberta-base`)로 팀 PC(Windows)에서 잰 p95 는 10KB 18ms, 100KB 152ms, 1MB 1.8초(세 형식 중 가장 느린 값)로 위 목표 안입니다. 1MB 한국어·영어 문서는 청크 700~800개라서 청크 상한 1000개는 약 1.2~1.4MB 문서에 해당합니다. 표는 `docs/preprocess_scope.md` 6절에 있습니다.
- (2026-10-26 확정) 복원 결과(`decoded_segments`)는 하나씩 따로 1차 분류기에 넣습니다. 한 청크의 복원 결과를 이어 붙이지 않습니다. 384토큰을 넘는 복원 결과는 청크와 같은 방식(384토큰, 50토큰 겹침)으로 자르고, 잘린 조각은 모두 그 복원 결과의 원문 인코딩 구간 전체(`span`)를 위치로 씁니다. 긴 Base64 덩어리 전체가 하이라이트되지만 틀린 위치는 아닙니다. 학습 데이터에도 복원 결과를 넣어 서빙과 같게 합니다. 서빙과 학습 모두 `preprocess.decoded` 의 `decoded_inputs`(청크 하나)·`decoded_texts`(학습 샘플 하나)로 같은 조각을 만듭니다. `html_entity`·`unicode_escape` 는 표기가 있는 줄 전체를 푼 글이라 앞뒤의 평범한 글도 함께 들어갑니다.
- (2026-10-31 추가, 정규화 1.1) ② HTML 숨김 판정에 `<style>` 블록의 단순 선택자 규칙(태그·클래스·ID, `@media` 안 포함)을 더합니다. 자손 선택자 등은 보지 않습니다. `href`·`src`·`data-*` 같은 주소·데이터 속성 값은 정리본에 넣지 않고 그 안의 인코딩만 ⑤ 에서 풀어 `decoded_segments` 에 넣습니다. 자리표시자나 긴 쿼리 값이 붙은 외부 이미지 주소(`<img src>`, MD 이미지)는 `hidden_text_found`(note `exfil_image`)로 표시합니다. ③ 에서 변형 선택자 3개 이상으로 숨긴 바이트를 해독해 `decoded_segments`(method `variation_selector`)에 넣습니다. 이 method 값을 위해 `common/schema.py` 의 `DecodedSegment.method` 에 `variation_selector` 를 더하고 `SCHEMA_VERSION` 을 0.2.4 로 올립니다. ④ 에서 키릴·그리스 문자로만 쓴 단어도 공격 키워드 목록(`preprocess.homoglyph.KEYWORDS`)에 있는 단어로 읽힐 때만 라틴 문자로 바꿉니다.
- 관련 코드: `common/schema.py` → `TransformLog`, `TransformSpan`, `DecodedSegment`

## ⑦ 2차 판정 실패 처리 (제안: 4단계 D)

- LLM 답변(JSON)을 읽지 못하면 1번 다시 묻고, 그래도 못 읽으면 차단합니다(fail-closed): `label="injection"`, `risk_score=1.0`, `confidence=0.0`.
- LLM 이 인용한 근거 문장을 `preprocess.quote.find_quote` 로 원문에서 찾지 못하면, 판정은 그대로 두고 `evidence_span` 만 비웁니다. 판정을 바꾸면 실제 공격을 놓칠 수 있기 때문입니다.
- 2차 서버가 응답하지 않을 때(fail-open / fail-closed)는 통합 담당과 확정합니다.
- 관련 코드: `stage2_llm/judge.py`, `stage2_llm/config.py` → `MAX_RETRIES`

## ⑧ 파이프라인 경계값 (5단계 ④) — 초안, 전원 리뷰 필요

- 1차 점수 θ_low=0.30 미만이고 룰 점수가 2차 경계(0.30) '이하'면 2차를 건너뜁니다(조기 종료). θ_high=0.80 이상이면 공격 확정입니다.
- 2차 경계는 "0.30 초과"입니다. 주석 신호(SIG-COMMENT)가 정확히 0.3 이라 "이상"으로 두면 HTML 주석 하나 있는 정상 문서도 전부 2차로 갑니다.
- 2차로 보내는 경로는 네 가지(1차 애매, 룰 의심, 위치 찾기, 재검사)이고 경로마다 따로 세어 로그에 남깁니다. 2차 호출률 예산(목표 15% 이하)은 1차 경로와 룰 경로가 나눠 씁니다.
- 값은 전부 초깃값입니다. B가 5주차에 룰을 켠 상태의 2차 호출률을 보고 θ를 확정하고, 정상 문서 기준선에서 룰 점수 구간별 비율을 재서 같은 PR 로 고칩니다.
- 관련 코드: `common/config.py` → `THETA_LOW`, `THETA_HIGH`, `RULE_TO_STAGE2`, `RULE_WARN`, `RULE_BLOCK`

## ⑨ 판정 합치기와 정책 (5단계 ⑤) — 초안, 룰 필터 담당과 확정 필요

- 룰·1차·2차 결과는 표(위에서 처음 맞는 줄)로 합칩니다. 표는 `pipeline/merge.py` 머리말에 있습니다.
- 룰 0.9 이상은 2차 결과와 상관없이 공격입니다. 룰 가이드가 "차단 후보"로 남긴 결정을 5단계(A)가 룰 담당과 확정하는 것으로 두었습니다. 받아들이면 보안 교육 글의 Base64 예시가 0.9 가 될 수 있으니, 인용문 점수 절반 규칙을 복원 글(+decoded)에도 적용해 달라고 요청합니다.
- "경고"는 판정 결과값입니다. 조각은 그대로 넘기고 화면·로그에 의심 표시만 합니다. 정책의 "경고 후 통과"(테스트·모니터링용)와 이름이 같지만 다릅니다.
- 조치 기본값은 마스킹입니다. 마스킹 위치 표와 순서는 `pipeline/policy.py` 머리말에 있습니다. 지울 위치가 없으면(본문 평문 공격 등) 2차에 위치만 묻고(위치 찾기 경로, 판정은 뒤집지 않음), 그래도 없으면 조각 전체를 차단합니다.
- 마스킹한 조각은 한 번만 재검사합니다. 재검사용 청크(`pipeline.policy.mask_chunk`)는 지운 구간 밖의 변환 기록·복원 결과만 담아, 룰의 `check_chunk` 를 고치지 않고 그대로 씁니다. 재검사에서 또 공격이면 조각 전체를 막습니다.
- 답변 LLM 은 원문이 아니라 마스킹한 정리본(text)을 받습니다. 원문 좌표는 화면 하이라이트에만 씁니다.
- 공격 구간은 문서 단위로 원문 좌표 합집합을 만들어 그 문서의 모든 조각에 적용합니다. 이것이 곧 겹침(50토큰) 중복 제거이고, 5단계 정책 엔진이 문서 단위로 한 번만 합니다. C·E 쪽에서 따로 하지 않아도 됩니다.
- 관련 코드: `pipeline/merge.py`, `pipeline/policy.py`, `common/config.py` → `DEFAULT_POLICY`, `MASK_MARKER`

## ⑩ 장애 정책 (5단계 ⑥) — 초안, fail-safe 방향 전원 합의 필요

- 공격자가 일으킬 수 있는 장애는 합의와 상관없이 막습니다: 전처리 예외·크기 상한 초과는 문서 전체 차단, 룰 예외는 그 조각 차단(나머지는 정상 진행), 2차 응답 형식 오류(다시 물어도 실패)는 조각 차단.
- 인프라 장애(1차 장애, 2차 서버 다운·시간 초과·회로 열림)는 합의한 fail-safe 로 처리합니다. 초깃값은 "경고로 통과"(fail-open + 경고 표시 + 재검사 대상 로그)입니다. fail-closed 로 바꾸면 2차 장애 동안 2차가 필요한 조각(1차 경로+룰 경로 합친 비율)이 정상 문서까지 모두 막힙니다 — 이 숫자를 보고 전원이 정합니다. 룰 0.9 이상과 1차 θ_high 이상은 fail-safe 와 상관없이 그대로 공격입니다.
- 장애 중에 내린 판정은 저장하지 않습니다(`Verdict.fallback=True`). 복구 뒤에도 정상 문서가 계속 막히는 것을 막기 위해서입니다.
- 로그 DB 쓰기가 실패해도 판정은 계속하고, 예비 파일(`data/inspection_log_fallback.jsonl`)에 쓰고 경고합니다.
- 전처리 처리 시간 상한은 가이드와 달리 두지 않습니다. ⑥ 전처리 원칙의 기존 결정(시간으로 끊으면 같은 문서의 결과가 컴퓨터 속도에 따라 달라져 학습·서빙이 어긋남)을 유지하고, 대신 크기 상한(파일·글자·복원·청크 수)이 같은 역할을 합니다.
- 2차 요청 하나의 타임아웃 30초, 동시 요청 상한 4, 회로 차단기는 연속 5번 실패에 열리고 30초 뒤 한 건만 보내 봅니다. 열고 닫힘은 로그(events)에 남습니다. 모두 부하 테스트(동시 1·4·16) 뒤 고칩니다.
- 관련 코드: `pipeline/orchestrator.py`, `pipeline/circuit.py`, `common/config.py` → `FAIL_SAFE_ACTION`, `STAGE2_TIMEOUT_S`, `STAGE2_MAX_CONCURRENT`, `CIRCUIT_*`

## ⑪ 버전과 판정 재사용 (5단계 ⑦) — 초안

- `pipeline_ver` = 전처리 `normalize.VERSION` + 룰 `RULE_VERSION` + 1차 모델 버전 + 2차 모델·프롬프트 버전 + 경계값 묶음. 요청 시작 때 한 번 계산해 Verdict 와 로그에 남깁니다.
- 저장된 판정은 `chunk_id` 로 찾고, 조각 원문 해시와 `pipeline_ver` 가 둘 다 맞을 때만 재사용합니다. 같은 문서ID 로 내용이 바뀐 문서가 들어와도 옛 판정이 쓰이지 않습니다. 같은 문서를 동시에 올려도 판정은 한 벌만 저장됩니다.
- 색인 단위 = 검사 단위: `split_document` 청크를 그대로 색인하고 임베딩은 정리본(text) 기준, 복원 청크는 색인하지 않습니다(①). 재사용 여부·장애 표시는 로그에 남겨 지연 그래프에서 뺄 수 있습니다.
- 재학습·규칙 수정·임계값 변경 뒤에는 `python -m pipeline.recheck --file ...` 로 색인 문서를 새 버전으로 일괄 재검사합니다. 레드팀 기간에는 판정이 바뀌는 수정(규칙 수정 포함)을 8주차로 미루고, 레드팀 1라운드 전에 git 태그 + `pipeline_ver` 로 통합 버전을 고정합니다(일정).
- 관련 코드: `pipeline/version.py`, `pipeline/store.py`, `pipeline/recheck.py`

## ⑫ 다른 단계에 요청한 것 (5단계, 4주차 전달)

- 룰 필터: `StageResult.evidence_spans` 에 걸린 위치 전부를 담는 코드는 5단계가 common PR 에서 같이 넣었습니다(`rule/filter.py`). 판정 합치기 표(⑨)와 룰 0.9 즉시 공격, 인용문 절반 규칙의 복원 글 적용을 같이 확정해 주세요. 전처리 버전이 바뀌면 룰 담당에게 알립니다(룰 가이드의 약속).
- B(3단계 학습·6단계 평가): 1차 모델 파일에 학습 때 쓴 `normalize.VERSION` 기록(`stage1/train.py` 의 meta 가 이미 저장 — 서빙에서 `_check_versions` 로 비교). θ 확정은 룰을 켠 상태의 2차 호출률로. 지연 그래프는 조각 단위와 요청 단위, 재사용·장애 표시를 구분.
- E(3단계 서빙): 1차 배치 입력 함수 모양 `score(chunks) -> list[StageResult]` 로 합의(스텁 `stage1/stub.py` 가 이 모양). 같은 프로세스 호출을 기본값으로 가정했습니다.
- C·D(4단계): 2차 인용문 여러 개(`evidence_quotes`) 목록화, 타임아웃·동시 상한 값, 형식 오류 fail-closed(⑦에 이미 있음) 확인.
- 7단계 화면: 하이라이트 좌표는 코드포인트 기준이므로 화면에서 UTF-16 으로 변환. "공격으로 차단"(룰·판정) / "검사 불가로 차단"(장애·형식 오류) / "경고" 를 구분해 표시 — 로그의 `fallback`·`reason` 칸으로 구분할 수 있습니다.
